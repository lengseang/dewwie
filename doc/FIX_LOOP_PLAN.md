# Dewwie Fix Loop Plan

Source: evaluation + system audit of 2026-11-20 (report: https://claude.ai/artifact/12AgFQS7aoKxB8m141R2Eq).
Worked by a self-paced `/loop` agent: **one task per iteration**, top to bottom.

## Rules for every iteration
1. Take the first task whose status is `[ ]`. If it is marked `NEEDS USER`, skip it.
2. Before editing, run `git status -s` and `dewwie room list` (`python cli/dewwie.py room list`). If another agent has uncommitted edits in a file you need, edit only lines outside their changed hunks; if impossible, mark the task `[!] blocked: <reason>` and move on.
3. Fix the root cause with the smallest correct diff. No refactors beyond the task.
4. Run the task's **Verify** commands plus the baseline gate:
   - `node --check desktop-ui/electron/main.cjs`
   - `cd desktop-ui && npx tsc --noEmit && npx vitest run && npm run build`
   - `python tests/run_all_tests.py` (must stay 12/12, and `~/.swarmherd` hashes must be unchanged by it)
5. On pass: change `[ ]` to `[x]`, append one `Evidence:` line (commands + result). On fail after 2 attempts: revert your edit for that task, mark `[!]`, and write why.
6. Post one line to the room: `python cli/dewwie.py room send "<task id> done/blocked: <summary>" --target '@all'`.
7. **Never commit, push, delete user data, or touch `release/`.** Commits are the user's call.
7b. **If the user's Dewwie app is running** (`dewwie.exe` / `electron.exe .` from `desktop-ui`), never kill it and never start an instance that shares its state. Live checks run in a **fully sandboxed instance** (`scratchpad/eval/sandbox_app.cjs`: USERPROFILE/HOME/APPDATA/LOCALAPPDATA -> temp, so it gets its own single-instance lock and its own `~/.swarmherd`); always hash the real `~/.swarmherd` before/after and confirm unchanged. Headless IPC checks use `scratchpad/eval/main_harness.cjs`. Note: the user's running app keeps the main.cjs it started with; main-process fixes reach them after a restart.
8. When no `[ ]` tasks remain, write a final summary at the bottom and stop the loop.

### T14 [!] Quitting Dewwie stalls or hangs while terminals are open (P1, found during T12, pre-existing). **Blocked: time-boxed, root cause narrowed but not found. No product change made.**
- Investigation (2026-11-20), all on throwaway traced copies of the app, quit via the app's own close path (`mainWindow.close()`, same as the title-bar X), no Playwright attached, timed until the OS process exits:
  | variant | close -> process exit |
  |---|---|
  | minimal hello-world Electron app, same electron.exe | **2.5 s / 5.3 s** (normal; Defender real-time scanning is on) |
  | Dewwie as-is | idle shell **> 45 s**, `ping -t` running 18.8 s |
  | node-pty stubbed out entirely | 21.5 s / 23.5 s |
  | powerSaveBlocker never started | > 45 s / 14.8 s |
  | single-instance lock removed | > 45 s / > 45 s |
